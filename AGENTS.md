# meteo

A SvelteKit app showing the weather for Nogent-sur-Marne. Read [README.md](README.md) first: it describes the data flow, the Météo-France auth trick, the page behavior and the deployment.

## What this app is not

- **No database, no sync layer, no secret.** Nothing to migrate, nothing to configure, no `.env`. If a change seems to need one of these, say so before adding it.
- **No navigation.** One page at `/`, three endpoints under `/api/`. There is no shell, no sidebar, no router beyond SvelteKit's own.
- **Online-only.** `src/service-worker.ts` exists solely so notifications work on Chrome for Android. Never give it a fetch handler or a cache: that would let it serve stale app code.

## Handoff

Multi-session work in progress has a handoff in `.agents/handoffs/<name>/`, holding `handoff.md` and its session logs. There is one right now: [meteo-bench-extraction](.agents/handoffs/meteo-bench-extraction/handoff.md), which still has to deploy the app and remove the bench from wyts-platform. A session opening with just "continue" goes there. When a second handoff appears, replace this pointer with a line saying to list `.agents/handoffs/` and pick the matching one.

Meteo's own code (page, grids, cells, columns, types, the Météo-France server module, the activity detector) was copied as is, so it still reads like wyts-platform code: two-space indentation, the same Prettier config. Keep it that way rather than restyling it.

## The UI kit is not stock

`Button`, `Checkbox` and `Label` under `src/lib/components/ui/` were copied from wyts-platform, not generated by the shadcn-svelte CLI. They carry wyts's customizations, and the page depends on two of them: the `outline` variant and the `icon-sm` size.

`components.json` is CLI metadata only (vega preset, neutral base, Lucide). Two traps if you reach for the CLI:

- The registry no longer serves the `slate` base color, and `init` now requires a design-system `--preset` whose IDs are opaque codes, so a plain non-interactive `init` is no longer possible.
- `pnpm dlx shadcn-svelte@latest` can resolve to a stale cached version that the live registry rejects. Pin the version explicitly.

Adding a component through the CLI would reset the theme tokens in `src/app.css`. Paste the component instead, or re-apply the palette afterwards.

## Styling

The wyts dark palette is in `src/app.css` as fixed tokens, with the `--wx-*` mapping the SVAR grids read. Grid-specific variables and the rules that change grid behavior live with the wrapper, `src/lib/components/DatagridTheme.svelte` — including the warning never to give that wrapper `display: flex`, `height: 100%` or `flex: 1`, which breaks SVAR's virtualization.

## Deploy

A push to `main` auto-deploys: Dokploy builds this repo's `Dockerfile` and serves it at `meteo.wyzar.io` through Traefik and a Cloudflare Tunnel. The container build itself is described in [README.md](README.md).

The one-time setup (Dokploy application, domain, tunnel ingress) goes through wyts-platform's `scripts/deployment/dokploy-api.ts` and `cloudflare-tunnel-setup.ts`; this repo deliberately carries no deployment scripts and has no secrets for them to manage. The tunnel needs nothing per app: a wildcard rule routes every `*.wyzar.io` host to Traefik (wyts-platform's `docs/development/deployment/networking-ingress.md`).

Dokploy application `meteo` is `6DxKJnAeV08TefWwctYRH` (swarm name `meteo-orjeii`), domain `wG2rfm2GnKo2UkPkLi207`. A build takes about a minute.

**Push auto-deploy does not work yet** (2026-10-29): Dokploy's GitHub App receives no push events, see "GitHub App" in wyts-platform's `docs/development/deployment/dokploy-platform.md`. Until it is fixed, redeploy by hand: from wyts-platform, `tsx --env-file=.env.development.local scripts/deployment/dokploy-api.ts post application.deploy '{"applicationId":"6DxKJnAeV08TefWwctYRH"}'`.

## Checks before a push

`pnpm check` (svelte-check) and `pnpm lint` (Prettier) must pass. A push to `main` deploys, so run them first.
